# Completion Report Standard

Keep it short; output tokens are the costly part. After finishing a task, report only:

- What changed and why (key files, decisions)
- Checks actually run, with results; what was not run
- Limitations/follow-ups and git actions, only if any

**Testing guide (only for user-facing changes):** add 2–5 lines: where to go, what to do, what should happen, plus one edge case. Skip it for internal, backend-only or trivial changes; do not write "no user-facing journey".
