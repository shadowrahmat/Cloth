# Technical Debt

Inspect code and architecture for duplication, complexity, fragile coupling, outdated dependencies, weak tests, and operational risks. Prioritize by impact, likelihood, remediation cost, and affected users. Separate immediate defects from long-term improvements. Recommend incremental changes and measurable outcomes. Do not perform broad refactors without approval.
