# Containers and infrastructure as code

- **Dockerfiles:** pinned base image versions (digest for production), multi-stage builds, minimal runtime image, non-root user, `.dockerignore`, no secrets in layers or build args (use build secrets), healthcheck, one process per container, exec-form entrypoints for signal handling, layer ordering for cache (dependencies before source).
- **Compose (local/dev):** service definitions with healthchecks and `depends_on` conditions, named volumes for data, env files not committed with secrets, resource limits where useful; production orchestration differs, do not assume Compose equals production.
- **Kubernetes/orchestrators (if used):** resource requests/limits, liveness vs readiness vs startup probes used correctly, rolling update settings, PodDisruptionBudgets, config and secrets via the platform's mechanisms, network policies, non-root security contexts, image pull policies, namespace separation. Follow the project's manifests/Helm/Kustomize conventions.
- **IaC (Terraform/OpenTofu, Pulumi, CloudFormation, Ansible):** all changes via code review; remote state with locking and encryption; plan before apply and review the plan; never apply to production without approval; modules with pinned versions; separate state per environment; avoid manual console changes (drift detection); tag resources for ownership and cost; secrets referenced from a secret manager, not in state or code (state can contain secrets: protect it).
- **Networking and security:** least-privilege IAM, private subnets for data stores, security groups/firewalls restricted, TLS termination and certificate renewal automation, WAF/rate limiting at the edge where appropriate, secrets rotation.
- **Hosting choices:** managed services reduce operational load; weigh cost, lock-in, compliance, team skills; document the decision (ADR).
- **Servers (VPS/bare metal):** configuration management, unattended security updates policy, SSH keys only, firewall, fail2ban-style protections, backups, monitoring, log rotation, systemd units with restart policies.
- **Validation:** `docker build`, `docker compose config`, `terraform validate/plan`, linters (hadolint, kube-linter, tflint) if present; report what could not be run.
